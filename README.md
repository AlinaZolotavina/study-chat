# LOM AI

Образовательный mock AI-чат: React 19, TypeScript 6, Vite 8, Redux Toolkit. Работают несколько диалогов, адаптивный streaming, Stop/Retry, Markdown, навигация, проявление схемы и локальное сохранение истории/черновиков. Доступны удаление с подтверждением, позиции чтения по чатам и плавный переход к новым сообщениям.

## Запуск

Node.js 22.23.2 указан в .nvmrc, npm — 10.9.8. Версии пакетов закреплены точно и сохранены в package-lock.json.

```sh
npm ci
npm run dev
```

По умолчанию: http://127.0.0.1:5173. Если порт занят, Vite выберет следующий; актуальный адрес будет в консоли.

| Команда            | Действие                                         |
| ------------------ | ------------------------------------------------ |
| npm run check      | Typecheck, ESLint, форматирование, запуск Vitest |
| npm run build      | Проверка типов и сборка в dist                   |
| npm run preview    | Просмотр сборки на http://127.0.0.1:4173         |
| npm run test:watch | Vitest в режиме наблюдения                       |
| npm run format     | Форматирование исходников и конфигурации         |

Vitest выполняет unit и четыре integration-теста. Фабрика createAppStore создаёт независимый store с внедряемыми agent, now, createId и getter storage; по умолчанию подключён локальный mock-agent. В main.tsx передаётся storage: () => window.localStorage; без getter фабрика работает в памяти для изоляции тестов. store.dispose() снимает подписку хранения, очищает debounce и отменяет запросы. Команды send/retry/stop/create/delete находятся в src/features/chat/model.

TypeScript 6.0.3 выбран по совместимости с typescript-eslint. Временный override minimatch 11.0.4 закрывает [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249); при обновлении линтера его нужно пересмотреть.

## Интерфейс

Оформление по предоставленному референсу: светлая палитра Mint & Teal, бирюзовые градиентные кнопки и знак-звезда. Подсказки и карточки примеров — на общем бледно-бирюзовом фоне без границ; отправленные вопросы выделены более насыщенным оттенком. Ширина колонки переписки и поля до 1040 px. Новых UI-зависимостей нет.

ChatWorkspace объединяет Sidebar, MessageList, Composer и уведомления хранения. Redux хранит чаты и черновики; DOM-ссылки, прокрутка и состояние загрузки изображения остаются в React. Компоненты подписываются на нужный чат или сообщение, фоновая генерация продолжается независимо от выбора диалога.

На desktop/tablet справа от уменьшенного бренда есть плавное сворачивание sidebar до 72 px (320 мс, reduced motion поддержан). В узкой панели только квадратные кнопки: раскрытие и новый чат сверху, справка снизу; у каждой доступное имя и title. Справа деликатная тень, справка открывается в общем dialog. Локальный флаг сохраняется при смене размеров, на телефоне не применяется, после reload панель развёрнута.

«О демоверсии» на всех экранах открывается в одном модальном окне: мягкий вход 220 мс и выход 160 мс с подложкой, reduced motion поддержан. Закрытие возвращает фокус кнопке справки. Справка текстом описывает три встроенных сбоя и Retry; отдельных кнопок запуска ошибок нет. Открытие и закрытие не меняют черновик или запрос. Автор ответа сделан вторичным: подпись 13 px и бирюзовый знак бренда 18 px без круглой подложки.

На телефоне компактная шапка 40 px + safe area содержит бренд и badge, ниже — шапка чата 45 px с бургером, названием и деликатной нижней тенью. Меню занимает 80% ширины и всю высоту: бренд в его шапке совпадает по позиции с закрытым состоянием, закрытие справа; новый чат — отдельно ниже. Шапка, новый чат и справка закреплены, список диалогов прокручивается отдельно; правый край имеет деликатную тень. Справка открывается поверх меню в нативном dialog; Tab/Escape/подложка и возврат фокуса поддержаны. Выбор/создание чата закрывают меню, фоновые ответы продолжаются. Локальный sidebarPanel сбрасывается при смене телефонного/широкого режима и reload; welcomeMark убран на всех экранах.

В списке чатов общая плашка выделяет иконку и название выбранного чата. При генерации контрастный градиент движется слева направо по плашке либо по тексту невыбранного чата, цикл 1400 мс; reduced motion отключает движение. Успешный фоновый ответ отмечается синей точкой до открытия чата, включая reload. Место индикатора зарезервировано, название не сдвигается; видимого «Готовит ответ» нет.

Enter отправляет, Shift+Enter переносит строку на всех экранах; клавиатурная подсказка видна только на desktop/tablet. У поля нет видимой подписи, доступное имя «Сообщение» сохранено. Во время ответа черновик доступен для редактирования, отправка отключена, доступна остановка. Лимит — 4000 UTF-16 единиц без обрезания текста. Учебные примеры заполняют только пустой черновик текущего чата без автоматической отправки.

Под последним успешным ответом доступны подсказки продолжения — кнопки со стилем пользовательских реплик. Нажатие сразу отправляет вопрос, сохраняя набранный draft. Набор вычисляется из успешной истории своего чата; при новом вопросе/active/ошибке/остановке скрывается. Использованный вопрос этапа исчезает после успешного ответа и не возвращается при ручном повторе/fallback/reload. Ошибка/Stop его не расходуют; новый этап получает свой вопрос. В Redux/localStorage подсказки отдельно не записываются.

react-markdown 10.1.0 отображает простой Markdown без HTML и встроенных изображений; кликабельны только абсолютные HTTP(S)-ссылки. Схема загружается из локального assets с учётом Vite base, без текстового пояснения/подписи; ошибка файла показывается отдельным сообщением.

Справа от статуса terminal-ответа с текстом доступно копирование исходного Markdown: после успеха Check на 1500 мс, при отказе — локальная ошибка. Готовую схему можно открыть целиком в тёмном просмотре без заголовка и скачать исходным PNG. Кнопка скачивания в обоих видах находится поверх изображения справа внизу на компактном тёмном фоне. Просмотр доступен после загрузки/проявления; Escape/фон/крестик закрывают его и возвращают фокус.

Статус под ответом раскрывает историю завершённых действий. Подписи задаются централизованно; внутренние рассуждения и raw-события не показываются. После успеха — «Думал 4,2 сек»: фактическое finishedAt − acceptedAt, включая операции, streaming и паузы. Run не ждёт CSS-проявления изображения. В run хранятся actions и expanded; раскрытие сразу сохраняется, переживает switch/reload. Ошибка/Stop оставляют выполненные действия, Retry начинает новую свёрнутую историю. Раскрытие доступно с клавиатуры, анимация отключается при reduced motion.

## Mock-agent

Команды распознаются по явному списку после нормализации; тема и шаг восстанавливаются только по пользовательским запросам из успешной истории. Тексты ответов не анализируются; ошибки и частичные ответы не продвигают учебный сценарий. Полные команды и синонимы — в [сценариях](docs/TECHNICAL_REQUIREMENTS.md#mock-сценарии).

- «Объясни второй закон Ньютона» → упрощение, схема и пример из жизни в любом порядке.
- «Помоги решить уравнение» → три «Дальше»: только 3(2x − 4) + 5 = 2(x + 7). На этапах 1–3 доступны «Дальше» и конкретный вопрос; адресное пояснение не продвигает решение. На четвёртом этапе x = 21/4 = 5,25 с проверкой и двумя вопросами о ней; нового уравнения не предлагается.
- «Сколько будет 17 × 24?» — вызов калькулятора, результат 408.
- Встроенные сбои: calculator до результата; переход уравнения 2 → 3 после трёх фрагментов; generate_image без PNG. Каждый вид один раз на чат, отметка сохраняется после фактической ошибки и переживает reload. Retry возвращает реальный результат, успешный учебный шаг учитывается один раз. Stop до ошибки её не расходует; Retry после такого Stop ещё может показать сбой. Отдельные команды ошибок удалены и обрабатываются fallback.
- Остальные формулировки — успешный fallback с сохранением учебной темы и прогресса. Повтор стартовой команды в текущей теме также не сбрасывает прогресс.

Агент выдаёт AsyncIterable событий с отменяемыми задержками. В src/agent: commands — распознавание, context — тема/шаг, scenarios/equation — учебные ответы, suggestions — продолжения, tools/calculator — умножение, tools/generateImage — подготовленный PNG/alt с отменяемой задержкой и управляемым сбоем, mockAgent — операции/события, streaming — блоки/фрагменты. Тесты инструментов находятся рядом в tools. В config.ts все диапазоны: анализ 300–600 мс, подготовка текста 200–400 мс; calculator — этапы 150–300 и 100–200 мс, подготовка текста 100–200 мс. Полный текстовый сценарий ≤ 4 с, calculator < 3 с и быстрее схемы при штатных таймерах. Изображение готовится 2500–3500 мс после анализа и завершает ответ без текста. Один статус/действие calculator, answer_composed после последней дельты либо готовой схемы; случайных ошибок нет.

Streaming: 80 слов/с ±10%, фрагменты 8–24 Unicode code points, паузы между абзацами/пунктами; заголовки и формулы ускорены. Разметка/пробелы сохраняются, незакрытый промежуточный Markdown допустим. Длительность блока не зависит от разбиения; длинные произвольные абзацы не ограничены двумя секундами. Random/config внедряются для фиксированных тестов. Схема не сравнивается по полной длительности с объяснением Ньютона.

## Локальное хранение

Один ключ lom-ai:chat содержит JSON чатов: порядок, выбранный ID, историю/run, черновики, частичный текст, относительные imageSrc с optional imageAlt, actions/expanded каждой попытки и demonstratedFailures своего чата. src/storage: validation проверяет базовую структуру, chatStorage читает данные и переводит все active в interrupted, persistence управляет одной подпиской и debounce 400 мс. ID и частичный результат сохраняются; автоматического продолжения нет, доступен Retry.

Создание/удаление чата, completed/cancelled/failed и раскрытие истории действий записываются сразу. Обычный debounce откладывает запись непрерывного streaming до паузы или завершения; несохранённые изменения при reload могут потеряться. При ошибке чтения исходный ключ не перезаписывается; при ошибке записи дальнейшие записи прекращаются до перезапуска. Приложение работает в памяти и показывает текстовое уведомление. Runtime, остальное UI-состояние и CSS-прогресс не сохраняются; миграций и синхронизации вкладок нет.

## Проверки и ограничения

npm run check выполняет проверку типов, ESLint, Prettier и 450 тестов Vitest (446 unit + 4 integration). Постоянных integration-сценариев четыре; требования к единственному E2E описаны в quality requirements, сам Playwright-тест пока не добавлен.

Интерфейс проверяется в Chrome: обычное окно, эмуляция desktop/tablet/mobile в DevTools и автоматические проверки в headless Chrome. По согласованию реальные устройства и другие браузеры в приёмку не входят; работа физической экранной клавиатуры и safe area не подтверждена. Фоновые таймеры браузера могут замедлять имитацию; несколько вкладок не синхронизируются. Последние изменения до debounce могут потеряться при reload. Старые ответы без actions/expanded не поддерживаются; миграций нет.
