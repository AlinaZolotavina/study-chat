# LOM AI

Образовательный mock AI-чат: React 19, TypeScript 6, Vite 8, Redux Toolkit. Реализованы основа, модель чатов, исполнитель, mock-agent и localStorage; в UI пока стартовый экран с уведомлениями об ошибках хранения. Следующий этап — интерфейс чата.

## Запуск

Node.js 22.23.2 указан в .nvmrc, npm — 10.9.8. Версии пакетов закреплены точно и сохранены в package-lock.json.

```sh
npm ci
npm run dev
```

По умолчанию: http://127.0.0.1:5173. Если порт занят, Vite выберет следующий; актуальный адрес будет в консоли.

| Команда            | Действие                                         |
| ------------------ | ------------------------------------------------ |
| npm run check      | Typecheck, ESLint, форматирование, запуск Vitest |
| npm run build      | Проверка типов и сборка в dist                   |
| npm run preview    | Просмотр сборки на http://127.0.0.1:4173         |
| npm run test:watch | Vitest в режиме наблюдения                       |
| npm run format     | Форматирование исходников и конфигурации         |

Vitest выполняет unit и четыре integration-теста. Фабрика createAppStore создаёт независимый store с внедряемыми agent, now, createId и getter storage; по умолчанию подключён локальный mock-agent. В main.tsx передаётся storage: () => window.localStorage; без getter фабрика работает в памяти для изоляции тестов. store.dispose() снимает подписку хранения, очищает debounce и отменяет запросы. Команды send/retry/stop/create/delete находятся в src/features/chat/model.

TypeScript 6.0.3 выбран по совместимости с typescript-eslint. Временный override minimatch 11.0.4 закрывает [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249); при обновлении линтера его нужно пересмотреть.

## Mock-agent

Команды распознаются по явному списку после нормализации; тема и шаг восстанавливаются только по пользовательским запросам из успешной истории. Тексты ответов не анализируются; демокоманды ошибок не сбрасывают учебную тему. Полные команды и синонимы — в [сценариях](docs/TECHNICAL_REQUIREMENTS.md#mock-сценарии).

- «Объясни закон Архимеда» → «Объясни проще» → «Покажи схему».
- «Помоги решить уравнение» → два «Дальше»: только 2x + 6 = 14.
- «Сколько будет 17 × 24?» — вызов калькулятора, результат 408.
- «Покажи ошибку» / «Покажи обрыв ответа» — сбой в первой попытке, успешный Retry.
- Остальные формулировки — завершённый ответ с примерами поддерживаемых запросов.

Агент выдаёт AsyncIterable событий с отменяемыми задержками. В src/agent: commands — распознавание, context — восстановление темы/шага, scenarios — ответы, calculator — умножение, mockAgent — события/streaming. Задержки, размер фрагмента и путь изображения собраны в config.ts; поток идёт по 16 Unicode code points. Запросы вызываются через store; UI чата ещё не подключён.

## Локальное хранение

Один ключ lom-ai:chat содержит JSON чатов: порядок, выбранный ID, историю/run, черновики, частичный текст и относительные imageSrc. src/storage: validation проверяет базовую структуру, chatStorage читает данные и переводит все active в interrupted, persistence управляет одной подпиской и debounce 400 мс. ID и частичный результат сохраняются; автоматического продолжения нет, доступен Retry.

Создание/удаление чата и completed/cancelled/failed записываются сразу. Обычный debounce откладывает запись непрерывного streaming до паузы или завершения; несохранённые изменения при reload могут потеряться. При ошибке чтения исходный ключ не перезаписывается; при ошибке записи дальнейшие записи прекращаются до перезапуска. Приложение работает в памяти и показывает текстовое уведомление. Runtime, UI и CSS-прогресс не сохраняются; миграций и синхронизации вкладок нет.

## Этапы реализации

Ориентир: один frontend-разработчик, 3 дня / около 24 часов; два дня оставляют мало резерва. Объём меняется по согласованию.

Статус: «Основа», «Модель и исполнитель», «Mock-agent» и «localStorage» выполнены. Проходят 229 тестов (225 unit + 4 integration), типы/lint/форматирование и production build. Проверена цепочка через два store: сохранение частичного ответа → interrupted без автозапуска → успешный Retry. Уведомления о сбоях чтения/записи проверены серверным рендером; браузерный E2E ещё не выполнялся. Следующий этап — основной UI чата.
