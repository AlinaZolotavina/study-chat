## Продукт и поведение

### Цель и границы

Локальный образовательный mock AI-чат для 7–11 классов: русский язык, спокойная светлая тема, полноценные desktop/tablet/mobile. Стек: React, TypeScript, Redux Toolkit. Ориентир — 2–3 рабочих дня, [план](../README.md#этапы-реализации) — на три дня.

Входят чаты, streaming, статусы, остановка/retry, учебный контекст, калькулятор, готовое изображение, ошибки, localStorage и публикация демонстрации на GitHub Pages. Не входят LLM/внешний AI API, backend, аккаунты/роли/курсы, вложения/голос, редактирование сообщений, варианты и ветвления ответов, поиск/переименование чатов, тёмная тема, LaTeX, экспорт/редактор изображения и физический симулятор.

### Правила чата

| Действие | Поведение |
| --- | --- |
| Начало / новый чат | Один пустой «Новый диалог», без сообщения-приветствия. Новый чат выбирается сразу; повторный клик в пустом чате без draft использует его же. При draft создаётся другой чат |
| Название / порядок | Первый вопрос: trim, переносы → пробелы, до 48 Unicode-символов с многоточием. Свежие создание/новый вопрос поднимают чат; switch, дельты и retry порядок не меняют. Равные timestamps не нарушают стабильность |
| Switch | Восстановить историю, draft, статус и UI-позицию чтения. Поток продолжается в исходном чате; можно запустить другой чат |
| Delete | Одно подтверждение с названием и предупреждением о потере данных/остановке. Отмена ничего не меняет. Подтверждение отменяет только свой run, удаляет чат/draft; соседний выбор и список сразу сохраняются |
| Выбор после delete | Для выбранного чата — следующий на его месте в списке, иначе предыдущий; если список пуст — новый чат. Удаление фонового не меняет выбор; поздние события не восстанавливают чат |
| Send | Сразу добавить вопрос и пустой ответ, затем очистить принятый draft. Один active на чат, без очереди; быстрые повторные действия не создают дубликат. Во время ответа draft редактируется, send запрещён, stop доступен |
| Stop | Немедленный cancelled; сохранены полученные text/imageSrc, поздние данные игнорируются. До image_received картинка не добавляется, ожидание убирается; начавшийся blur может закончиться |
| Error | Локальная ошибка под сохранённым результатом, вопрос остаётся; другие чаты работают. Unsupported-вопрос, stop и отказ storage не являются ошибками генерации |
| Retry | Только последний failed/cancelled/interrupted до следующего вопроса; для failed нужен retryable. Те же ID вопроса/ответа, новый runId, attempt + 1, text/imageSrc/ошибка очищаются. Draft не меняется, двойной retry запускает один run |
| Новый вопрос после сбоя | Старый результат/отметка остаются, его retry скрывается; неуспешная пара исключается из контекста |

Ошибки воспроизводятся детерминированно; успешный ответ не перегенерируется. Chain of thought, сырые события, внутренние ID/ошибки и журнал инструментов не показываются.

### Ввод

- Многострочный draft каждого чата обновляется на ввод, сохраняется при switch/stop/error/retry.
- Нельзя отправить пустой/пробельный текст или исходный draft длиннее 4000 UTF-16 единиц (JS string.length). Счётчик, если есть, использует ту же меру. При превышении draft не обрезается; показана ошибка, send запрещён. При принятии trim только внешних пробелов, внутренние переносы сохраняются.
- На всех экранах Enter отправляет, Shift+Enter переносит. Видимая кнопка отправки использует ту же команду и проверки; при active остаётся disabled, рядом появляется stop.
- Примеры только заполняют пустое поле, без autosend. При непустом draft недоступны; примеры ошибок работают так же. Фокус — по UI-спецификации.

### Mock-сценарии

| ID | Запрос | Результат |
| --- | --- | --- |
| S-01 | «Объясни закон Архимеда» | Выталкивающая сила, плотность жидкости и объём вытесненной жидкости; Fₐ = ρ · g · V |
| S-02 | После S-01: «Объясни проще» | Бытовой пример погружённого предмета, та же тема; предложить «Покажи схему», без автоматической картинки |
| S-03 | После S-02: «Покажи схему» | Подготовка → готовое локальное изображение Архимеда → короткое streaming-пояснение |
| S-04 | «Помоги решить 2x + 6 = 14, но не давай ответ сразу» | Предложить вычесть 6 с обеих сторон, без значения x; попросить «Дальше» |
| S-05 | Два «Дальше» после S-04 | Сначала 2x = 8 и предложение разделить на 2; затем x = 4 и проверка 2 · 4 + 6 = 14 |
| S-06 | «Сколько будет 17 × 24?» | tool_call/result calculator → streaming с 408 |
| S-07 | Неподдержанный вопрос | Успешный дружелюбный fallback с границами демоверсии и 2–3 примерами |
| S-08 | «Покажи ошибку» | В attempt = 1 сбой до текста; retry успешен |
| S-09 | «Покажи обрыв ответа» | В attempt = 1 несколько дельт, затем сбой; retry успешен |

Нормализация команд: без учёта регистра, внешних пробелов и конечной пунктуации. Уравнение фиксированное; допускает пробелы и x/х. Калькулятор: два целых от −10000 до 10000, знаки ×, *, x, х, пробелы и оболочка «Сколько будет …?». Без eval и универсального solver; остальные форматы → fallback.

Приоритет: команды ошибок → контекстные продолжения → калькулятор → начало уравнения → Архимед → fallback. «Проще», «Покажи схему» и «Дальше» без подходящей темы вызывают уточнение. Повтор «проще» и изображение сохраняют Архимеда; «Дальше» после решения сообщает о завершении. Калькулятор/fallback начинают свою тему.

История запроса фиксируется на старте: только успешные completed-пары этого чата до текущего вопроса; prompt отдельно один раз. Частичные/неуспешные пары, черновики и статусы исключаются. Тема выводится из истории, без скрытой общей памяти.

### Время и изображение

Все задержки настраиваются в одном месте, без случайных сбоев.

| Этап | Время |
| --- | --- |
| queued → started / обработка | 150 / 450 мс |
| Калькулятор / подготовка изображения | 500 / 800 мс |
| Подготовка текста после результата | 200 мс |
| Streaming | 8–20 символов каждые 50 мс, без разрыва Unicode code point |
| Watchdog | 30 секунд |

Обычный ответ — примерно 2–8 секунд; фоновые таймеры браузера могут замедляться. Timeout, исключение, ранний конец итератора и нарушение протокола обязаны завершать run и освобождать ресурсы.

Предоставленный PNG находится в public/assets; путь подключения, размеры и alt уточняются на этапе изображения. Агент выдаёт preparing_image → image_received с локальным путём, без инструмента-генератора; обязательный инструмент — calculator. Placeholder, ошибка загрузки и условия blur заданы UI/дизайном. Текст может поступать одновременно с проявлением.

### localStorage

- Один ключ lom-ai:chat, обычный JSON RootState.chats: чаты/порядок/выбранный ID, сообщения/run, draft, частичный текст и локальные imageSrc. Без версий/миграций и менеджера снимков.
- На запуске: нет ключа → начальный чат; корректный JSON с базовой структурой → восстановление. queued/processing/streaming → interrupted с сохранением text/imageSrc; автоматического продолжения/повтора нет.
- Изменения: debounce 400 мс (допустимый диапазон 300–500). Создание/удаление и completed/cancelled/failed — сразу, с отменой debounce. Записывается актуальный store; bootstrap-изменения — при доступном storage. Последние ещё не записанные изменения при reload могут потеряться.
- Ошибка чтения/разбора/структуры → пустой чат и уведомление; старый ключ не исправлять/перезаписывать, запись выключена до конца сессии. Ошибка записи → продолжить в памяти с однократным уведомлением. Нет циклических повторов записи.
- Runtime, UI/scroll и CSS-прогресс исключены. Изображение при открытии чёткое. Нет синхронизации вкладок и автоматического восстановления повреждений; данные привязаны к браузеру/origin, не аккаунту.

### Формат сообщений

Markdown агента: абзацы, переносы, списки, выделения, заголовки, цитаты, код без подсветки, ссылки; skipHtml, без raw HTML, таблиц/расширений и картинок из Markdown. Пользовательский текст — обычный текст. Ссылки только абсолютные http/https, новая вкладка и rel="noopener noreferrer"; остальные URL — неактивный текст.

Длинные слова/URL переносятся; у кода собственный горизонтальный скролл, у страницы его нет. Частичный Markdown не падает и не запускает анимацию всего текста заново.

## Архитектура

### Стек

| Область | Решение и причина |
| --- | --- |
| UI / сборка | React + TypeScript strict + Vite: клиентское SPA без серверного рендеринга |
| Состояние | Redux Toolkit + React Redux: независимые чаты, явные события |
| Асинхронность | Тонкие thunks → один requestExecutor; mock-agent возвращает AsyncIterable |
| Представление | CSS Modules и CSS-переменные; Radix Dialog для drawer и единого подтверждения; react-markdown с skipHtml |
| Изображение | Готовый локальный asset, обычный img |
| Хранение | Один JSON в localStorage, простая подписка с debounce |
| Проверки | Vitest, Playwright, TypeScript, ESLint, Prettier; объём — в [плане](QUALITY_REQUIREMENTS.md#автоматизация) |

При реализации закрепить совместимые стабильные версии, npm lock-файл и Node.js LTS. Основания: [Vite](https://vite.dev/guide/), [Redux Style Guide](https://redux.js.org/style-guide/), [thunk extraArgument](https://redux.js.org/usage/writing-logic-thunks). Router, RTK Query, backend, сетевой streaming-протокол, worker, дополнительные middleware и state-machine библиотеки не нужны. Выбор чата не отражается в URL и истории браузера.

| --- | --- |
| src/app | Bootstrap, store, сервисы, провайдеры, глобальные стили |
| src/features/chat/model | Типы, slice, selectors, thunks, requestExecutor; зависит от контракта agent и shared |

Типы сообщений принадлежат chat model, событий — agent. Изображение передаётся строкой imageSrc. Циклические импорты, модуль диаграмм и абстракции ради будущего роста не вводятся.

### Владение состоянием

| Где | Данные |
| --- | --- |
| Redux | Чаты, сообщения, последняя попытка каждого ответа, черновики, выбранный ID, storageStatus |
| requestExecutor, один на store | Map запусков с AbortController, задачами и watchdog |
| Подписка storage | Таймер debounce |
| Устойчивый React UI | Drawer/disclosure, chatIdToDelete, focus, blur; useRef с `Map<ChatId, ScrollState>` для scrollTop/followBottom |

UI-состояние и runtime не сериализуются. Scroll-сервис и инфраструктура модальных окон не нужны; детали — в [UI](#ui). Активность, canSend/canRetry и статусы выводятся селекторами, без дублирующих флагов.

### Исполнение

Путь: UI → thunk → requestExecutor → mock-agent → синхронные действия slice → selectors → UI.

1. Исполнитель проверяет актуальный store, создаёт ID/время и историю запроса; до первого await одним действием добавляет вопрос и пустой ответ, очищает отправленный draft и обновляет список.
2. Регистрирует контроллер и читает события. Reducer только синхронно проверяет принадлежность/переход и меняет данные; await, таймеры, вызовы агента и генерация ID в нём запрещены.
3. Stop сначала фиксирует cancelled, затем abort. Retry сохраняет ID вопроса/ответа, создаёт новый runId и очищает результат. Switch меняет только выбранный чат.
4. Один deleteChat отменяет свой run через существующий исполнитель и атомарно удаляет чат с выбором соседа/созданием пустого; UI закрывает общий диалог и удаляет scroll-запись.
5. При terminal, исключении или отмене исполнитель закрывает итератор и освобождает только свой handle. Старый finally не удаляет новый run.

Agent, clock, ID factory и исполнитель внедряются через extraArgument. Вся оркестрация сосредоточена в requestExecutor; mock знает только сценарии и события. Guard runId, терминальная блокировка и обработка ошибок — по [контракту](#данные-и-события). serializableCheck остаётся включённым; [правило RTK](https://redux-toolkit.js.org/usage/usage-guide/#working-with-non-serializable-data).

Bootstrap читает storage до рабочего экрана, переводит active в interrupted и подключает одну подписку. Начальное/восстановленное изменённое состояние сохраняется при доступном storage. storageStatus не запускает запись по кругу. Правила сохранения принадлежат ТЗ.

### Отрисовка

Sidebar подписывается на порядок ID и стабильные метаданные строк; история — на свой чат. Фоновая дельта не перестраивает открытую историю. Достаточны мемоизированные селекторы без сплошной мемоизации и виртуализации: ожидаются десятки чатов и сотни сообщений.

Текст накапливается строкой, частичный Markdown допустим. ImageBlock, открытый с готовым imageSrc, не повторяет анимацию; живой переход из ожидания использует правила [дизайна](#дизайн). CSS-прогресс не является состоянием запроса.

### Размещение

На этапе передачи опубликовать статическую сборку dist через GitHub Pages/GitHub Actions после успешных проверок и сборки; фактическую ссылку добавить в README. Серверная часть не нужна.

Vite base определяется адресом публикации: /<repo>/ для project Pages, / для сайта в корне домена. JS, CSS и изображение должны учитывать эту базу; URL локального asset строится с import.meta.env.BASE_URL. Имя репозитория и URL берутся из реального проекта, без предположений по имени рабочей папки. Основание — [Vite: GitHub Pages](https://vite.dev/guide/static-deploy#github-pages).

## Данные и события

### Состояние и сообщения

ChatId, MessageId, RunId, ToolCallId — именованные string; Timestamp — ISO 8601 UTC. ID уникальны, не индексы; новый RunId на каждую попытку. ID/clock внедряются, значения создаются вне reducer; в браузере допустим crypto.randomUUID.

| Тип | Поля |
| --- | --- |
| RootState.chats | byId: `Record<ChatId, Chat>`; order: ChatId[]; selectedChatId: ChatId |
| RootState.app | storageStatus: available либо unavailable с reason: read_error / write_error |
| Chat | id: ChatId; title: string; createdAt: Timestamp; lastQuestionAt: Timestamp или null; draft: string; messages: Message[] |
| Message, общие поля | id: MessageId; createdAt: Timestamp; role — discriminator |
| UserMessage, role = user | text: string |
| AssistantMessage, role = assistant | replyToMessageId: MessageId; text: string; imageSrc: string или null; run: Run |

Ключ byId совпадает с Chat.id; order содержит каждый чат один раз, selectedChatId существует. После bootstrap есть хотя бы один чат. lastQuestionAt меняется только на новый вопрос. Сообщения идут парами user → assistant; replyToMessageId указывает на непосредственно предшествующий вопрос. Пустой ответ создаётся сразу. Приветствия и технические сообщения в историю не добавляются.

Команда send формирует корректную пару; reducer requestAccepted защищает инвариант перед записью: replyToMessageId совпадает с ID вопроса, ID сообщений различаются, ответ имеет status = queued, пустой text и imageSrc = null. Нарушение отклоняется без изменения state, включая draft, историю, метаданные и порядок чатов.

imageSrc — известный путь к предоставленному asset относительно публичной базы приложения, не внешний URL, base64 или путь на диске пользователя. При отображении он разрешается с учётом Vite base. Alt, загрузка файла и анимация принадлежат UI; отдельной модели изображения/геометрии нет.

Drawer, chatIdToDelete, scroll Map, focus и blur не входят в RootState или localStorage. Их локальные типы заданы в [UI](#ui).

### Run и фазы

Общие поля Run: id: RunId, attempt: положительное целое от 1, acceptedAt: Timestamp, status — discriminator.

| status | Дополнительные поля |
| --- | --- |
| queued | Нет |
| processing | phase: ProcessingPhase |
| streaming | Нет |
| completed | finishedAt: Timestamp |
| failed | finishedAt: Timestamp; error: AgentError |
| cancelled | finishedAt: Timestamp |
| interrupted | finishedAt: Timestamp; reason = reload |

Активные: queued / processing / streaming; остальные терминальные. У завершённого состояния нет активной phase, у успешного — error.

| ProcessingPhase.kind | Данные |
| --- | --- |
| analyzing / preparing_image / composing | Нет |
| using_tool | callId: ToolCallId; tool = calculator |

AgentError: code = demo_failure / demo_partial_failure / tool_failure / timeout / unexpected_end / protocol_error / unknown; retryable: boolean. Пользовательский текст берётся по code из [UI](#ui). Нормализованные mock/timeout/неожиданные ошибки допускают повтор; raw Error и stack trace не сохраняются.

### Запрос агента

| Тип | Поля |
| --- | --- |
| AgentRequest | chatId: ChatId; assistantMessageId: MessageId; runId: RunId; attempt: положительное целое; prompt: string; history: readonly AgentHistoryTurn[] |
| AgentHistoryTurn | userText: string; assistantText: string |

History — неизменяемая копия успешных пар до текущего prompt, без самого prompt и imageSrc. Правила контекста — в ТЗ. Производный mock-контекст: none / archimedes / equation с шагом / calculator; общей переменной темы нет. AbortSignal передаётся отдельным runtime-аргументом.

### События

Один вызов возвращает упорядоченный `AsyncIterable<AgentEvent>`. Общий envelope: chatId: ChatId, assistantMessageId: MessageId, runId: RunId, at: Timestamp, type — discriminator.

| type | Payload | Переход / изменение |
| --- | --- | --- |
| started | Нет | queued → processing/analyzing |
| phase_changed | phase = analyzing / preparing_image / composing | processing вне using_tool → новая фаза |
| tool_call | callId: ToolCallId; tool = calculator; input: operation = multiply, left/right: integer | processing/analyzing или composing → using_tool |
| tool_result | callId: ToolCallId; tool = calculator; output: value: number | Совпадающий using_tool → composing |
| image_received | imageSrc: string | preparing_image → composing; сохранить путь |
| text_delta | text: непустая string | analyzing/composing → streaming; далее дополнять text |
| completed | Нет | streaming с непустым text → completed |
| error | error: AgentError | Любое активное → failed |

Калькулятор использует результат для текста, отдельная таблица результатов не нужна. Изображение возвращается самостоятельным событием, без tool_call/tool_result. Номера сетевых событий, reconnect и журнал инструментов не вводятся.

Команды приложения: send создаёт queued; stop переводит активный run в cancelled, затем abort; restore переводит сохранённый active в interrupted; retry заменяет run на новый queued с attempt + 1, очищая text/imageSrc, но сохраняя ID сообщений. Агент не присылает cancelled/interrupted.

### Защита событий и runtime

1. Нет чата/assistant нужного ID, не совпал runId, попытка уже terminal или не относится к последнему assistant — игнорировать событие.
2. Для текущего active проверить переход и callId/tool. Нарушение, включая completed без текста, завершает run как failed/protocol_error.
3. После terminal исполнитель прекращает чтение. Конец итератора без terminal → unexpected_end; исключение → нормализованная ошибка; watchdog → timeout, затем abort. Поздний AbortError не заменяет terminal причиной cancelled.

RuntimeRegistry внутри requestExecutor: RunId → handle с chatId, assistantMessageId, AbortController, задачей и watchdog. Регистрация после синхронного queued, до async-работы. Все delay учитывают signal и очищают таймер/abort-listener; finally удаляет только собственный handle. Завершение приложения/тестового store отменяет задачи и снимает storage-подписку.

Инварианты: максимум один active на чат, только у последнего assistant; state и обычные actions сериализуемы; terminal не принимает данные; retry не дублирует вопрос и не меняет draft; switch не управляет потоком; delete влияет только на свой run. Полученное изображение может остаться при ошибке последующего текста.

### Селекторы и JSON

selectedChat, orderedChatIds, chatRowMetadata(title/активность/ошибка), chatMessages, activeRun, canSend, canRetry, agentStatusLabel — производные значения, не копии state. Проверки canSend/canRetry заданы ТЗ.

В localStorage записывается только RootState.chats: byId, order, selectedChatId. При чтении проверить базовые типы, существование выбранного ID, массивы messages, строки draft и основные поля сообщений/run. Без глубокого аудита связей, исправления данных и миграций. При active → interrupted убрать phase, добавить finishedAt, сохранить text/imageSrc. StorageStatus, runtime и UI исключаются; остальные правила — в ТЗ.

## UI

### Экран и компоненты

Шапка → независимо прокручиваемая история → composer; sidebar имеет собственный скролл. Desktop/tablet показывают постоянную панель, телефон — модальный drawer. На границах режимов доступна одна версия навигации; смена режима/ориентации не теряет чат, draft и run. Высота учитывает viewport, экранную клавиатуру и safe area; страница не прокручивается вместе с историей.

Фокус после отправки остаётся в поле. После выбора чата на телефоне drawer закрывается, фокус — на заголовке, без самопроизвольной клавиатуры. Фоновое завершение не переключает чат и не показывает тост успеха.

### Одно подтверждение удаления

Устойчивый компонент области чатов хранит chatIdToDelete: ChatId | null. Любая кнопка удаления задаёт ID; один Radix Dialog выводит имя/предупреждение, включая active-вариант. Начальный focus — «Отмена»; Escape/закрытие сбрасывают ID без изменения чата.

Один confirm вызывает deleteChat по правилам ТЗ. После успеха ID сбрасывается и scroll-запись удаляется. После отмены focus возвращается на кнопку удаления; после удаления фонового — на ближайший выбор в списке (drawer остаётся открытым), выбранного — на заголовок нового выбора (drawer закрывается). На удалённом DOM focus не остаётся. Отдельные модальные варианты и сервис удаления не нужны.

### Прокрутка

Устойчивый UI-компонент, не размонтируемый при switch, хранит useRef с `Map<ChatId, ScrollState>`. Локальный ScrollState: scrollTop: number, followBottom: boolean. Один основной контейнер сообщений; без Redux/localStorage, scroll-сервиса, middleware, IntersectionObserver и наблюдателей для каждого сообщения.

| Событие | Действие |
| --- | --- |
| Scroll / перед switch | Сохранить scrollTop; расстояние scrollHeight − clientHeight − scrollTop ≤ 80 px означает followBottom = true, иначе false |
| Рост текста/содержимого | Только при followBottom двигаться к концу; рост DOM сам не выключает следование |
| Пользователь выше порога | Позицию не менять; доступна «К новым сообщениям», в том числе при поступлении дельт |
| Кнопка перехода | Конец истории, обновить позицию, включить followBottom |
| Switch | После отрисовки сообщений (например, useLayoutEffect) восстановить конец при followBottom, иначе сохранённый scrollTop в допустимом диапазоне |
| Нет записи / reload / собственный send | Показать конец, followBottom = true |
| Resize / клавиатура | Сохранить то же правило чтения; новые данные не переводят focus в историю |
| Delete | Удалить запись из Map |

Для оставленного выше чата рост в фоне не меняет место чтения. Кнопка перехода не перекрывает текст.

### Изображение и движение

Готовый asset закона Архимеда через img: вписать без обрезки и искажения, сохранить пропорции, не растягивать бесконтрольно. Размер placeholder резервируется по файлу; на 320 px изображение/подпись не расширяют страницу. Alt уточняется по файлу, подпись остаётся обычным читаемым текстом.

Только живое получение в выбранном чате с переходом из ожидания запускает после загрузки файла эффект 1200 мс: blur 16 px → 0, opacity 0,25 → 1. Размывается только изображение; блок стабилен по высоте, blur не выходит за его границы. Пояснение может одновременно поступать потоком. Готовый результат при switch/reload и открытии фонового ответа сразу чёткий, без повторного эффекта. CSS-прогресс не сохраняется; stop не обязан обрывать начавшийся эффект.

Обычные переходы — 120–160 мс; streaming без анимации каждого слова. При prefers-reduced-motion нет blur/opacity-анимации, плавной прокрутки и вращения: готовая картинка сразу чёткая, активность показана статически. Проверки размеров, состояний и базовой доступности — в [плане](QUALITY_REQUIREMENTS.md#ручная-приёмка).
