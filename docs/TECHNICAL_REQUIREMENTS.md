## Продукт и поведение

### Цель и границы

Локальный образовательный mock AI-чат для 7–11 классов: русский язык, спокойная светлая тема, полноценные desktop/tablet/mobile. Стек: React, TypeScript, Redux Toolkit. Ориентир — 2–3 рабочих дня, [план](../README.md#этапы-реализации) — на три дня.

Входят чаты, streaming, статусы, остановка/retry, учебный контекст, калькулятор, готовое изображение, ошибки, localStorage и публикация демонстрации на GitHub Pages. Не входят LLM/внешний AI API, backend, аккаунты/роли/курсы, вложения/голос, редактирование сообщений, альтернативные версии ответов и ветвление истории, поиск/переименование чатов, тёмная тема, LaTeX, экспорт/редактор изображения и физический симулятор.

### Правила чата

| Действие | Поведение |
| --- | --- |
| Начало / новый чат | Один пустой «Новый диалог», без сообщения-приветствия. Новый чат выбирается сразу; повторный клик в пустом чате без draft использует его же. При draft создаётся другой чат |
| Название / порядок | Первый вопрос: trim, переносы → пробелы, до 48 Unicode-символов с многоточием. Свежие создание/новый вопрос поднимают чат; switch, дельты и retry порядок не меняют. Равные timestamps не нарушают стабильность |
| Switch | Восстановить историю, draft, статус и UI-позицию чтения; снять отметку непрочитанного. Поток продолжается в исходном чате; можно запустить другой чат |
| Непрочитанный ответ | Успешное завершение в невыбранном чате ставит синюю точку справа от названия до открытия чата, включая reload. В выбранном чате, после ошибки/Stop или позднего события отметка не появляется |
| Delete | Одно подтверждение с названием и предупреждением о потере данных/остановке. Отмена ничего не меняет. Подтверждение отменяет только свой run, удаляет чат/draft; соседний выбор и список сразу сохраняются |
| Выбор после delete | Для выбранного чата — следующий на его месте в списке, иначе предыдущий; если список пуст — новый чат. Удаление фонового не меняет выбор; поздние события не восстанавливают чат |
| Send | Сразу добавить вопрос и пустой ответ, очистить принятый draft только при отправке из composer. Подсказка отправляется напрямую с сохранением draft. Один active на чат, без очереди; быстрые повторные действия не создают дубликат. Во время ответа draft редактируется, send запрещён, stop доступен |
| Stop | Немедленный cancelled; сохранены полученные text/imageSrc, поздние данные игнорируются. До успешного tool_result(generate_image) картинка не добавляется, ожидание убирается; начавшийся blur может закончиться |
| Error | Локальная ошибка под сохранённым результатом, вопрос остаётся; другие чаты работают. Unsupported-вопрос, stop и отказ storage не являются ошибками генерации |
| Retry | Только последний failed/cancelled/interrupted до следующего вопроса; для failed нужен retryable. Те же ID вопроса/ответа, новый runId, attempt + 1, text/imageSrc/ошибка очищаются. Draft не меняется, двойной retry запускает один run |
| Новый вопрос после сбоя | Старый результат/отметка остаются, его retry скрывается; неуспешная пара исключается из контекста |

Ошибки воспроизводятся детерминированно; успешный ответ не перегенерируется. Chain of thought, сырые события, внутренние ID, входы/результаты инструментов и технические ошибки не показываются. Разрешена история завершённых высокоуровневых действий по правилам ниже.

### Ввод

- Многострочный draft каждого чата обновляется на ввод, сохраняется при switch/stop/error/retry.
- Нельзя отправить пустой/пробельный текст или исходный draft длиннее 4000 UTF-16 единиц (JS string.length). Счётчик, если есть, использует ту же меру. При превышении draft не обрезается; показана ошибка, send запрещён. При принятии trim только внешних пробелов, внутренние переносы сохраняются.
- На всех экранах Enter отправляет, Shift+Enter переносит. Видимая кнопка отправки использует ту же команду и проверки; при active остаётся disabled, рядом появляется stop.
- Примеры только заполняют пустое поле, без autosend. При непустом draft недоступны. Фокус — по UI-спецификации.

| --- | --- | --- |
| S-01 | «Объясни второй закон Ньютона» / «Расскажи о втором законе Ньютона» / «Второй закон Ньютона» / «2 закон Ньютона» | F = m · a, a = F / m; равнодействующая сила, масса, ускорение; три независимых продолжения |

| S-04 | «Помоги решить уравнение» / «Помоги решить уравнение 3(2x − 4) + 5 = 2(x + 7), но не давай ответ сразу» | Только фиксированное уравнение: первый этап раскрытия скобок, без конечного ответа |
| S-05 | После S-04: «Дальше» / «Продолжай» / «Следующий шаг»; уточнения ниже | Три перехода к этапам 2–4; пояснения сохраняют текущий этап |
| S-06 | «Сколько будет 17 × 24?» / «7*24» и прежняя грамматика умножения | После встроенного сбоя: tool_call/result calculator → streaming с 408 / 168 соответственно |
| S-07 | Неподдержанный вопрос или уточнение вне своего этапа | Успешный дружелюбный fallback; учебная тема и прогресс сохраняются, актуальные подсказки возвращаются |
| S-08 | Встроен в S-06 | calculator: ошибка tool_failure до результата; Retry возвращает правильное вычисление |
| S-09 | Встроен в S-05 при переходе 2 → 3 | Первые три фрагмента настоящего объяснения переноса слагаемых → stream_failure; Retry возвращает полный ответ третьего этапа |
| S-10 | Встроен в S-03 после объяснения Ньютона | generate_image: tool_failure без изображения; Retry возвращает PNG без текста |

Команды — полное совпадение с таблицей и уточнениями ниже. Нижний регистр, trim, серии пробельных символов → один пробел; конечные . , ; : ! ? … игнорируются. Операторы * / - % не удаляются. Для сопоставления фиксированной математики − и - равнозначны, допускаются пробелы и x/х; слово «уравнение» в длинной команде необязательно. Прочие уравнения и произвольные формулировки → fallback, без поиска ключевых слов и семантического анализа. Калькулятор прежний: два целых от −10000 до 10000, ×, *, x, х и оболочка «Сколько будет …?». Без eval и универсального solver. Отдельных команд ошибок нет; прежние формулировки «Покажи ошибку», «Покажи обрыв ответа», «Покажи ошибку создания изображения» обрабатываются fallback.

Приоритет команд: контекстные продолжения/уточнения → калькулятор → начало уравнения → Ньютон → fallback. После выбора учебного сценария определяется встроенный сбой. Каждый вид S-08–S-10 возникает один раз на чат, независимо от числа попыток; отметки calculator/equation/image сохраняются в demonstratedFailures. Отметка добавляется только вместе с принятой ошибкой своего активного run; Stop, timeout, reload и поздние события до ошибки её не расходуют. Retry после фактического сбоя и следующие запросы этого вида успешны; Retry после Stop до ошибки ещё может показать неиспользованный сбой. Отметки не являются учебным контекстом.

Повтор старта в текущей теме не сбрасывает выполненные действия/этап; известная другая тема начинает свой сценарий. Калькулятор устанавливает свою тему после успеха. Fallback, ошибки и частичные ответы сохраняют тему/прогресс; успешный Retry применяет исходную учебную команду ровно один раз. Повтор выполненного действия Ньютона вручную допустим, в подсказках оно больше не предлагается.

| Этап уравнения | Результат и пояснение | Подсказки до использования |
| --- | --- | --- |
| 1 | 6x − 12 + 5 = 2x + 14; распределительное свойство | «Дальше», «Почему нужно раскрывать скобки?» |
| 2 | 6x − 7 = 2x + 14; −12 + 5 = −7 | «Дальше», «Почему −12 + 5 = −7?» |
| 3 | 4x = 21; вычесть 2x и прибавить 7 в обеих частях | «Дальше», «Почему при переносе меняется знак?» |
| 4 | x = 21/4 = 5,25; подстановка в исходное уравнение даёт 24,5 с обеих сторон | «Покажи проверку подробнее», «Объясни, как проверить ответ» |

«Дальше» продвигает только уравнение, после этапа 4 сообщает о завершении. Конкретные «Почему…» работают на своём этапе, вопросы проверки — только на четвёртом. Пояснения не продвигают решение и не раскрывают конечный ответ до этапа 4; после успешного пояснения использованный вопрос убирается, остаётся «Дальше». Ответ даётся непосредственно на вопрос, с необходимой частью выражения, без объявления номера этапа и технических фраз о сохранении состояния/запрете перехода; основной ответ целиком не повторяется. Общая команда «Объясни подробнее» удалена; ручной ввод обрабатывается fallback. Нового уравнения и действия «Решить ещё одно уравнение» нет. Отвеченные вопросы проверки убираются из подсказок; после обоих подсказок нет.

Синонимы уточнений уравнения: этап 2 — «Почему получилось -7?» (− равнозначен -); этап 3 — «Почему поменялся знак?» / «Почему изменился знак?» / «Почему меняется знак?»; этап 4 — «Объясни проверку» / «Объясни проверку решения» означают объяснение способа проверки. Синонимы используют те же ответы, ограничения этапа и отметки использованных подсказок; отдельными действиями не считаются.

История фиксируется на старте: только completed-пары своего чата до текущего вопроса; prompt отдельно один раз. Частичные/неуспешные пары, draft и статусы исключаются. Контекст восстанавливается разбором пользовательских запросов; тексты ответов не используются. Скрытой общей памяти нет.

### Подсказки продолжения

- Только под последним completed-ответом, пока не принят следующий вопрос; одновременно один набор. При active/failed/cancelled/interrupted подсказок нет.
- Вычисляются чистой функцией из контекста успешной истории: у Ньютона — невыполненные из «Объясни проще», «Покажи схему», «Приведи пример из жизни»; у уравнения — по таблице. Не дополнять набор искусственно до 2–3 вариантов.
- Нажатие сразу отправляет текст как обычный вопрос через send/thunk/requestExecutor, сохраняя draft. Общие проверки ID/длины/active; команда проверяет наличие текста в текущем доступном наборе, исполнитель — ожидаемый ID последнего completed-ответа. Устаревший или использованный вариант отклоняется без изменений. Принятие синхронно создаёт одну пару/один run и скрывает набор; повторное нажатие не дублирует запрос.
- Использованный вопрос этапа исключается после completed, независимо от выбора кнопки или ручного ввода. Повтор вручную допустим, но не возвращает вопрос в набор. После ошибки/Stop вопрос не расходуется; active/неуспешный ответ по-прежнему скрывает весь набор.
- На этапах 1–3 после пояснения остаётся только «Дальше»; переход сбрасывает отметку и даёт вопрос нового этапа. Fallback/повтор старта не сбрасывают её; уточнение не своего этапа не расходует текущий вопрос.
- После ответа набор пересчитывается; после контекстного fallback возвращаются только ещё доступные действия. Учебные примеры заполняют только пустое поле текущего чата без autosend. При непустом draft кнопки примеров недоступны с пояснением; набранный текст не заменяется. В справке только текстовое описание встроенных сбоев. Обычный новый чат повторно использует текущий пустой.
- Подсказки не сообщения и не отдельные поля Redux/localStorage. После switch/reload вычисляются из истории своего чата; неуспешное действие не считается выполненным.

### Время и изображение

Все временные параметры — в src/agent/config.ts; случайность меняет только длительности/размеры фрагментов, не сценарии, тексты или исходы ошибок. Источник random внедряется в createMockAgent; фиксированные диапазоны min = max и variance = 0 используются в тестах. Длительность выбирается один раз при запуске операции/блока и остаётся локальной переменной генератора.

| Этап | Время |
| --- | --- |
| queued → started | 150 мс |
| Анализ / подготовка текста | Анализ 300–600 мс, подготовка текста 200–400 мс; у calculator подготовка 100–200 мс; у схемы текста нет |
| Калькулятор | Использование 150–300 мс, затем доставка результата 100–200 мс; один статус using_tool и одна запись calculated. Полный запрос со streaming < 3 с при штатных таймерах, быстрее минимального запроса схемы |
| Подготовка изображения | После анализа 2500–3500 мс; готовый PNG без streaming текста |
| Streaming | 80 слов/с ±10%, минимум 80 мс на обычный блок; 8–24 Unicode code points в дельте, последний фрагмент блока может быть короче |
| Заголовок / отдельная формула | 100 слов/с, 60–150 мс с учётом вариативности |
| Паузы | Между абзацами 100–150 мс, пунктами списка 60–100 мс |
| Watchdog | 30 секунд |

Для абзаца base = max(80 мс, words × 1000 / 80); длительность выбирается в base ±10% с сохранением минимума. Полное время каждого существующего текстового сценария от принятия до terminal, включая операции/streaming/паузы, ≤ 4 с при штатных таймерах; тексты не сокращаются. Длинный произвольный абзац не ограничен двумя секундами. Заголовки/формулы ускорены; списки идут пунктами. Фрагменты переменного размера не привязаны к словам, не рвут суррогатные пары; сумма задержек фрагментов равна выбранной длительности блока. Итоговая конкатенация точно сохраняет Markdown, пробелы и переносы; промежуточная незакрытая разметка допускается. Полноценный Markdown-парсер не нужен: разбираются строки/абзацы, пункты, заголовки и fenced-блоки подготовленных ответов.

Длительность схемы не сравнивается с полным объяснением Ньютона. Все существующие ответы проверяются на верхних значениях настроек в пределах watchdog; фоновые таймеры браузера могут замедляться. Timeout, исключение, ранний конец итератора и нарушение протокола завершают run и освобождают ресурсы.

Предоставленный PNG public/assets/newtons-2nd-law-of-motion.png, 1672×941; путь assets/newtons-2nd-law-of-motion.png. Для S-03 со встроенным S-10 агент вызывает generate_image через общие события инструментов, без text_delta. Успешный результат сохраняется до completed независимо от CSS; запрос не ждёт загрузки файла/анимации. Calculator возвращает прежний результат после встроенного сбоя и Retry.

### Generate_image

Самостоятельный mock-модуль по принципу calculator, без UI/Redux и нового реестра/исполнителя инструментов. Вход: topic = newton, imageType = educational_diagram; успех: status = success, относительный imageSrc и описательный alt. Тема сопоставляется с существующим PNG; новых учебных тем/изображений и внешних сервисов нет. Отменяемая задержка 2500–3500 мс настраивается через имеющуюся конфигурацию. Первый дошедший до ошибки запрос схемы расходует S-10 своего чата; после этого Retry и следующие запросы успешны. Ошибка нормализуется как tool_failure, не создаёт imageSrc/imageAlt и не добавляет image_prepared/answer_composed. Время image-tool запроса, включая сбой, не относится к лимиту текстовых сценариев 4 с.

Путь: tool_call(generate_image, callId, input) → tool_result с тем же tool/callId → сохранение imageSrc/imageAlt → image_prepared → answer_composed → completed. Результат сохраняет reducer; UI не вызывает инструмент. Отдельный image_received в новом рабочем протоколе не нужен. Сохраняются runId/terminal guard, watchdog и изоляция AbortController. Событие результата и запись «Использовал генератор изображений» не дублируют друг друга в истории действий.

### localStorage

- Один ключ lom-ai:chat, обычный JSON RootState.chats: чаты/порядок/выбранный ID, сообщения/run, draft, частичный текст, локальные imageSrc, отметки непрочитанного и demonstratedFailures. Без версий/миграций и менеджера снимков.
- На запуске: нет ключа → начальный чат; корректный JSON с базовой структурой → восстановление. queued/processing/streaming → interrupted с сохранением text/imageSrc; автоматического продолжения/повтора нет.
- Изменения: debounce 400 мс (допустимый диапазон 300–500). Создание/удаление, completed/cancelled/failed, раскрытие истории действий и отметки непрочитанного — сразу, с отменой debounce. Записывается актуальный store; bootstrap-изменения — при доступном storage. Последние ещё не записанные изменения при reload могут потеряться.
- Ошибка чтения/разбора/структуры → пустой чат и уведомление; старый ключ не исправлять/перезаписывать, запись выключена до конца сессии. Ошибка записи → продолжить в памяти с однократным уведомлением. Нет циклических повторов записи.
- Runtime, scroll, прочее локальное UI-состояние и CSS-прогресс исключены; раскрытие истории действий expanded сохраняется в run. Изображение при открытии чёткое. Нет синхронизации вкладок и автоматического восстановления повреждений; данные привязаны к браузеру/origin, не аккаунту.

### Формат сообщений

Markdown агента: абзацы, переносы, списки, выделения, заголовки, цитаты, код без подсветки, ссылки; skipHtml, без raw HTML, таблиц/расширений и картинок из Markdown. Пользовательский текст — обычный текст. Ссылки только абсолютные http/https, новая вкладка и rel="noopener noreferrer"; остальные URL — неактивный текст.

Длинные слова/URL переносятся; у кода собственный горизонтальный скролл, у страницы его нет. Частичный Markdown не падает и не запускает анимацию всего текста заново.

### Владение состоянием

| Где | Данные |
| --- | --- |
| Redux | Чаты, сообщения/run с actions и expanded, черновики, выбранный ID, storageStatus |
| requestExecutor, один на store | Map запусков с AbortController, задачами и watchdog |
| Подписка storage | Таймер debounce |
| Устойчивый React UI | sidebarPanel: null / chats / about, sidebarCollapsed: boolean, chatIdToDelete, focus, blur; useRef с `Map<ChatId, ScrollState>` для scrollTop/followBottom |

Локальное UI-состояние и runtime не сериализуются. Исключение — expanded конкретного run: его требуется восстанавливать после reload. Scroll-сервис и инфраструктура модальных окон не нужны; детали — в [UI](#ui). Активность, canSend/canRetry, статусы и подсказки выводятся селекторами. Учебный контекст и подсказки не дублируются в store.

### Исполнение

Путь: UI → thunk → requestExecutor → mock-agent → синхронные действия slice → selectors → UI.

1. Исполнитель проверяет актуальный store, создаёт ID/время и историю запроса; до первого await одним действием добавляет вопрос и пустой ответ, очищает draft при обычной отправке или сохраняет его при подсказке и обновляет список.
2. Регистрирует контроллер и читает события. Reducer только синхронно проверяет принадлежность/переход и меняет данные; await, таймеры, вызовы агента и генерация ID в нём запрещены.
3. Stop сначала фиксирует cancelled, затем abort. Retry сохраняет ID вопроса/ответа, создаёт новый runId и очищает результат. Switch меняет выбранный чат и снимает его отметку непрочитанного.
4. Один deleteChat отменяет свой run через существующий исполнитель и атомарно удаляет чат с выбором соседа/созданием пустого; UI закрывает общий диалог и удаляет scroll-запись.
5. При terminal, исключении или отмене исполнитель закрывает итератор и освобождает только свой handle. Старый finally не удаляет новый run.

Agent, clock, ID factory и исполнитель внедряются через extraArgument. Вся оркестрация сосредоточена в requestExecutor; mock знает только сценарии и события. Guard runId, терминальная блокировка и обработка ошибок — по [контракту](#данные-и-события). serializableCheck остаётся включённым; [правило RTK](https://redux-toolkit.js.org/usage/usage-guide/#working-with-non-serializable-data).

Bootstrap читает storage до рабочего экрана, переводит active в interrupted и подключает одну подписку. Начальное/восстановленное изменённое состояние сохраняется при доступном storage. storageStatus не запускает запись по кругу. Правила сохранения принадлежат ТЗ.

### Отрисовка

Sidebar подписывается на порядок ID и стабильные метаданные строк; история — на свой чат. Фоновая дельта не перестраивает открытую историю. Достаточны мемоизированные селекторы без сплошной мемоизации и виртуализации: ожидаются десятки чатов и сотни сообщений.

Текст накапливается строкой, частичный Markdown допустим. ImageBlock, открытый с готовым imageSrc, не повторяет анимацию; живой переход из ожидания использует правила [дизайна](#дизайн). CSS-прогресс не является состоянием запроса.

## Данные и события

### Состояние и сообщения

ChatId, MessageId, RunId, ToolCallId — именованные string; Timestamp — ISO 8601 UTC. ID уникальны, не индексы; новый RunId на каждую попытку. ID/clock внедряются, значения создаются вне reducer; в браузере допустим crypto.randomUUID.

| Тип | Поля |
| --- | --- |
| RootState.chats | byId: `Record<ChatId, Chat>`; order: ChatId[]; selectedChatId: ChatId |
| RootState.app | storageStatus: available либо unavailable с reason: read_error / write_error |
| Chat | id: ChatId; title: string; createdAt: Timestamp; lastQuestionAt: Timestamp или null; draft: string; messages: Message[]; unreadRunId?: RunId; demonstratedFailures?: DemoFailureKind[] |
| Message, общие поля | id: MessageId; createdAt: Timestamp; role — discriminator |
| UserMessage, role = user | text: string |
| AssistantMessage, role = assistant | replyToMessageId: MessageId; text: string; imageSrc: string или null; imageAlt?: string; run: Run |

Ключ byId совпадает с Chat.id; order содержит каждый чат один раз, selectedChatId существует. После bootstrap есть хотя бы один чат. lastQuestionAt меняется только на новый вопрос. Сообщения идут парами user → assistant; replyToMessageId указывает на непосредственно предшествующий вопрос. Пустой ответ создаётся сразу. Приветствия и технические сообщения в историю не добавляются.

unreadRunId — ID успешного запуска, завершённого в фоне; отсутствие поля означает прочитанный чат. Отметка снимается при выборе, включая автоматическое открытие соседа после удаления; выбранный чат не помечается непрочитанным. Селектор строки возвращает hasUnreadReply без зависимости от потокового текста.

DemoFailureKind = calculator / equation / image; demonstratedFailures содержит уникальные израсходованные сбои своего чата. Новый чат начинает с []; отсутствие поля в прежнем JSON равнозначно []. Executor передаёт копию списка при send/retry. Reducer отмечает сбой только вместе с валидной ошибкой: calculator/image при соответствующем using_tool + tool_failure, equation при streaming + stream_failure. Запись ошибки и отметки атомарная и немедленная; учебная история не используется как счётчик сбоев.

Команда send формирует корректную пару; reducer requestAccepted защищает инвариант перед записью: replyToMessageId совпадает с ID вопроса, ID сообщений различаются, ответ имеет status = queued, пустой text, imageSrc = null, imageAlt отсутствует, actions = [], expanded = false. Нарушение отклоняется без изменения state, включая draft, историю, метаданные и порядок чатов. В payload допустим preserveDraft: boolean (по умолчанию false); true для отправки подсказки.

imageSrc — известный путь к предоставленному asset относительно публичной базы приложения, не внешний URL, base64 или путь на диске пользователя. При отображении он разрешается с учётом Vite base. imageAlt приходит от generate_image и сохраняется с результатом; поле необязательное, для существующего PNG без него используется текущий alt. При Retry очищать оба поля, при interrupted сохранять полученные. Загрузка/анимация принадлежат UI; отдельной модели геометрии и хранения Blob/Base64 нет. Временный Blob для скачивания не является хранением готового результата.

Drawer, chatIdToDelete, scroll Map, focus и blur не входят в RootState или localStorage. Их локальные типы заданы в [UI](#ui).

### Run и фазы

Общие поля Run: id: RunId, attempt: положительное целое от 1, acceptedAt: Timestamp, actions: CompletedAgentAction[], expanded: boolean, status — discriminator. CompletedAgentAction: id: string, kind: analyzed / calculated / image_prepared / answer_composed, completedAt: Timestamp. Новая попытка начинается с actions = [] и expanded = false; runBase сохраняет эти поля при переходах.

| status | Дополнительные поля |
| --- | --- |
| queued | Нет |
| processing | phase: ProcessingPhase |
| streaming | Нет |
| completed | finishedAt: Timestamp |
| failed | finishedAt: Timestamp; error: AgentError |
| cancelled | finishedAt: Timestamp |
| interrupted | finishedAt: Timestamp; reason = reload |

Активные: queued / processing / streaming; остальные терминальные. У завершённого состояния нет активной phase, у успешного — error.

| ProcessingPhase.kind | Данные |
| --- | --- |
| analyzing / composing | Нет |
| using_tool | callId: ToolCallId; tool = calculator / generate_image |

AgentError: code = stream_failure / tool_failure / timeout / unexpected_end / protocol_error / unknown; retryable: boolean. Прежние demo_failure/demo_partial_failure допустимы только для чтения сохранённых ответов. Пользовательский текст берётся по code из [UI](#ui). Нормализованные mock/timeout/неожиданные ошибки допускают повтор; raw Error и stack trace не сохраняются.

### Запрос агента

| Тип | Поля |
| --- | --- |
| AgentRequest | chatId: ChatId; assistantMessageId: MessageId; runId: RunId; attempt: положительное целое; prompt: string; history: readonly AgentHistoryTurn[]; demonstratedFailures: readonly DemoFailureKind[] |
| AgentHistoryTurn | userText: string; assistantText: string |

History — неизменяемая копия успешных пар до текущего prompt, без самого prompt и imageSrc. Правила контекста — в ТЗ. Производный mock-контекст: none / newton с simplified, diagramShown, exampleShown / equation с шагом 1–4, questionAnswered для одного вопроса текущего этапа и verificationDetailed, verificationExplained / calculator; общей переменной темы нет. AbortSignal передаётся отдельным runtime-аргументом.

### События

Один вызов возвращает упорядоченный `AsyncIterable<AgentEvent>`. Общий envelope: chatId: ChatId, assistantMessageId: MessageId, runId: RunId, at: Timestamp, type — discriminator.

| type | Payload | Переход / изменение |
| --- | --- | --- |
| started | Нет | queued → processing/analyzing |
| phase_changed | phase = analyzing / composing | processing вне using_tool → новая фаза; соответствует status из описания UI |
| action_completed | actionId: string; action = analyzed / calculated / image_prepared / answer_composed | Добавить завершённое действие в actions с at → completedAt; текущую фазу не менять |
| tool_call | callId: ToolCallId; tool и input — связанный union: calculator с operation = multiply, left/right; generate_image с topic = newton, imageType = educational_diagram | processing/analyzing или composing → using_tool |
| tool_result | callId: ToolCallId; связанный union: calculator с value; generate_image с status = success, imageSrc, alt | Совпадающий using_tool → composing; для generate_image сохранить imageSrc/imageAlt |
| text_delta | text: непустая string | analyzing/composing → streaming; далее дополнять text |
| completed | Нет | streaming с непустым text либо composing/streaming с полученным imageSrc → completed; полностью пустой ответ запрещён |
| error | error: AgentError; optional demoFailure = calculator / equation / image | Активное → failed; валидный встроенный сбой атомарно отмечается в своём чате |

Калькулятор использует результат для текста, generate_image — для imageSrc/imageAlt. Отдельная таблица результатов не нужна. Номера сетевых событий, reconnect и сырые журналы инструментов не вводятся. История высокоуровневых действий формируется только из action_completed; tool_result не добавляет вторую запись. Проверять payload по имени инструмента, совпадение tool/callId, безопасный путь и непустой alt. Новые вызовы изображений используют using_tool; существующие незавершённые снимки, в том числе с прежним preparing_image, при чтении переводятся в interrupted. В новом runtime эта фаза не нужна, сложные миграции не вводятся.

Команды приложения: send создаёт queued; stop переводит активный run в cancelled, затем abort; restore переводит сохранённый active в interrupted; retry заменяет run на новый queued с attempt + 1, очищая text/imageSrc/imageAlt/actions и сбрасывая expanded, но сохраняя ID сообщений. Агент не присылает cancelled/interrupted. executionExpandedChanged меняет только expanded указанного сообщения/run, включая terminal; текст, история действий и выполнение запроса не меняются.

### Защита событий и runtime

1. Нет чата/assistant нужного ID, не совпал runId, попытка уже terminal или не относится к последнему assistant — игнорировать событие.
2. Для текущего active проверить переход и callId/tool. action_completed: analyzed только при analyzing, calculated при composing, image_prepared при composing с полученным imageSrc; answer_composed допустим при тех же условиях готовности результата, что completed. Queued и незавершённая операция не принимают действие. ID непустой, время валидно. Повтор actionId в своём run игнорируется; одинаковые kind с разными ID сохраняются в порядке поступления. Нарушение, включая completed без текста и изображения, завершает run как failed/protocol_error.
3. После terminal исполнитель прекращает чтение. Конец итератора без terminal → unexpected_end; исключение → нормализованная ошибка; watchdog → timeout, затем abort. Поздний AbortError не заменяет terminal причиной cancelled.

RuntimeRegistry внутри requestExecutor: RunId → handle с chatId, assistantMessageId, AbortController, задачей и watchdog. Регистрация после синхронного queued, до async-работы. Все delay учитывают signal и очищают таймер/abort-listener; finally удаляет только собственный handle. Завершение приложения/тестового store отменяет задачи и снимает storage-подписку.

Инварианты: максимум один active на чат, только у последнего assistant; state и обычные actions сериализуемы; terminal не принимает данные агента; retry не дублирует вопрос и не меняет draft; switch не управляет потоком; delete влияет только на свой run. Полученное изображение может остаться при ошибке последующего текста.

### Селекторы и JSON

selectedChat, orderedChatIds, chatRowMetadata(title/активность/ошибка), chatMessages, activeRun, canSend, canRetry, agentStatusLabel, chatSuggestions — производные значения, не копии state. Проверки canSend/canRetry заданы ТЗ.

В localStorage записывается только RootState.chats: byId, order, selectedChatId. При чтении проверить базовые типы, существование выбранного ID, массивы messages, строки draft и основные поля сообщений/run. Без глубокого аудита связей, исправления данных и миграций. При active → interrupted убрать phase, добавить finishedAt, сохранить text/imageSrc/imageAlt/actions/expanded. Валидировать обязательные actions/expanded, типы/время и уникальность actionId внутри run. Совместимость со старым форматом ответов, миграции и достраивание истории не требуются. StorageStatus, runtime и остальное локальное UI исключаются; остальные правила — в ТЗ.

Шапка и новый чат закреплены сверху, «О демоверсии» снизу; только список между ними прокручивается (flex: 1, min-height: 0, overflow-y: auto). Меню закрывается выбором/созданием чата, крестиком, Escape или кликом по подложке; фокус возвращается к бургеру, после выбора/создания — к заголовку без открытия клавиатуры.

«О демоверсии» открывает отдельный dialog поверх меню; после закрытия фокус возвращается к кнопке справки. В справке нет действий отправки. ChatDialog удерживает Tab/Shift+Tab, фон неактивен. Появление меню: slide слева и opacity 0,75 → 1 за 320 мс, cubic-bezier(0.22, 0.61, 0.36, 1); подложка проявляется за 240 мс. При reduced motion оба эффекта отключены. matchMedia через useSyncExternalStore переключает одну навигацию; смена телефонного/широкого режима закрывает окна. sidebarPanel не сериализуется и после reload закрыт; на desktop/tablet about открывается самостоятельно и закрывается в null, на телефоне возвращает chats.

### Копирование, просмотр и скачивание

Дополнительный UI-этап, без изменения mock-agent, сценариев, streaming и схемы localStorage. Используется текущий локальный PNG; внешние URL/генераторы и новые форматы источников не добавляются.

- **Копирование:** иконка Copy справа от кнопки статуса, раскрывающей операции, у непустого текста assistant, только при terminal: completed/failed/cancelled/interrupted. При active, пустом тексте и у user кнопки нет. Копируется полный сохранённый message.text с исходным Markdown, без статуса, истории действий и URL изображения. Clipboard API вызывается по нажатию; только после успешного Promise — Check на 1500 мс, затем Copy. Пока операция выполняется/показано подтверждение, повторный запуск блокируется. Недоступный API/отказ — локальный неблокирующий текстовый статус, без ложного успеха.
- **Готовность изображения:** просмотр и Download доступны после загрузки файла и окончания blur; при reduced motion/открытии готовой истории — после загрузки. Полученное изображение при Stop/ошибке остаётся доступным. Placeholder и ошибка файла не открываются. Схема остаётся без текстового пояснения, Copy под ней не появляется.
- **Просмотр:** отдельный переиспользуемый компонент на существующем ChatDialog, overlay на весь viewport, тёмный фон и центрированное изображение целиком, без обрезки/изменения исходника. Видимого заголовка нет; доступное имя окна — «Изображение схемы». Это модальный просмотр, без обязательного browser Fullscreen API, zoom/панорамирования. X, Escape и клик по фону закрывают; клик по изображению не закрывает. Focus удерживается в окне и возвращается к изображению. Пользовательская прокрутка фона заблокирована; после закрытия сохраняются позиция чтения и правило followBottom. Switch/delete исходного чата закрывают просмотр.
- **Скачивание:** отдельная круглая кнопка 44×44 поверх правого нижнего угла самого изображения, в сообщении и просмотре. Фон только по размеру кнопки: тёмный полупрозрачный overlay (black 55%, backdrop blur 10 px), иконка белая; hover темнее. Один общий обработчик/флаг выполнения. Получить исходный Blob по тому же безопасному локальному URL с учётом Vite base, проверить ответ и инициировать download через временный object URL; имя lom-ai-newton.png. Не использовать canvas, превью или новую генерацию. Ошибки получения файла/наблюдаемые ошибки запуска — неблокирующий статус. Подтверждение записи на диск/обнаружение отмены пользователем браузер не гарантирует; «Файл сохранён» не показывать. Повторные клики во время операции игнорировать.
- **UI и ресурсы:** собственный Icon получает Copy/Check/Download, X уже есть. Кнопки-иконки без видимого текста, aria-label/title, цель 44×44 и обычные hover/focus/active. Открытие изображения доступно Enter/Space, Download — отдельный соседний DOM-элемент поверх изображения, без вложенных button. Pending/copied/error/viewer и временные ресурсы только в React, без Redux/storage. При Retry/смене runId/switch/delete очищать таймеры, запросы и object URL, игнорировать завершения старых операций; результат копирования не относится к новой попытке. Не запускать blur заново из-за действий с изображением и не смещать историю уведомлениями/переключением иконок.

### История действий ответа

- Источник текущего статуса — run.status/phase, не случайная подпись. Обычный ответ: analyzed → answer_composed; калькулятор добавляет calculated, схема — image_prepared. Ошибки сохраняют только уже завершённые действия; успешного финального действия при сбое нет. Поиск и новые комбинации инструментов не входят в scope.
- analyzed отмечается после анализа; calculated после обоих внутренних этапов calculator и его tool_result, image_prepared после tool_result(generate_image); answer_composed после последней дельты либо получения схемы без текста, перед completed. Подготовка текста — внутренний этап формирования ответа, отдельного действия в истории не создаёт.
- Подписи действий: «Проанализировал запрос», «Выполнил вычисление с помощью калькулятора», «Использовал генератор изображений», «Сформировал ответ». Не выводить raw payload, параметры/числовой результат инструмента и внутренние ID.
- Кнопка с chevron, aria-expanded/aria-controls, min-height 44 px, видимым focus; Enter/Space работают нативно. При пустой истории — «Завершённых действий пока нет». При failed кнопка «История действий», текст ошибки отдельно; stopped/interrupted сохраняют нейтральный статус.
- У каждого run собственные actions/expanded. Кнопка работает и для старшего ответа в чате; проверяются ChatId/MessageId/RunId. Технические события не создают новых сообщений. Retry начинает новую свёрнутую историю и не принимает поздние события/клики предыдущей попытки.
- Маркированный список под кнопкой, без нумерации и тяжёлой карточки, цвет/кегль вторичны относительно ответа; chevron поворачивается. Раскрытие 160 мс, при reduced motion без переходов; изменение статуса и streaming не запускают раскрытие заново.

### Одно подтверждение удаления

Устойчивый компонент области чатов хранит chatIdToDelete: ChatId | null. Любая кнопка удаления задаёт ID; один ChatDialog выводит имя/предупреждение, включая active-вариант. Начальный focus — «Отмена»; Escape/закрытие сбрасывают ID без изменения чата.

Один confirm вызывает deleteChat по правилам ТЗ. После успеха ID сбрасывается и scroll-запись удаляется. После отмены focus возвращается на кнопку удаления; после удаления фонового — на ближайший выбор в списке (drawer остаётся открытым), выбранного — на заголовок нового выбора (drawer закрывается). На удалённом DOM focus не остаётся. Отдельные модальные варианты и сервис удаления не нужны.

### Прокрутка

Кнопка «К новым сообщениям»: фон gradientAccent, текст onAccent и radius 14 px как у «Новый диалог», стрелка вниз сохранена. JumpBar накладывается на нижнюю часть истории без изменения высоты scroll-контейнера; под кнопкой два backdrop-слоя 4/12 px с плавными масками сверху вниз. Нажатия/прокрутка вне кнопки проходят к истории, кнопка остаётся чёткой. На phone при высоте < 700 px jump-кнопка компактнее: min-height 40 px, шрифт 13 px, стрелка 16 px; при 700 px и выше — прежние 44 px. На телефоне отступы jumpBar — 12px 12px 8px. Это оформление не меняет правила прокрутки.

Устойчивый UI-компонент, не размонтируемый при switch, хранит useRef с `Map<ChatId, ScrollState>`. Локальный ScrollState: scrollTop: number, followBottom: boolean. Один основной контейнер сообщений; без Redux/localStorage, scroll-сервиса, middleware, IntersectionObserver и наблюдателей для каждого сообщения.

ChatWorkspace владеет Map; MessageList сохраняет позицию по scroll и через savePosition до смены чата, восстанавливает после DOM в useLayoutEffect. Один ResizeObserver только на основном контейнере учитывает смену его ширины/высоты (sidebar, composer, viewport); сообщения отдельно не наблюдаются. Текст/раскрытие действий обрабатываются существующим layout-эффектом. Browser scroll anchoring отключён, чтобы он не менял сохранённую позицию. Временное состояние перехода локально в MessageList; scrollend и резервная пауза scroll-событий 150 мс завершают его. Observer, слушатели и таймер очищаются при размонтировании, удалённая запись Map не создаётся заново из cleanup.

| Событие | Действие |
| --- | --- |
| Scroll / перед switch | Сохранить scrollTop; расстояние scrollHeight − clientHeight − scrollTop ≤ 80 px означает followBottom = true, иначе false |
| Рост текста/содержимого | Только при followBottom двигаться к концу; рост DOM сам не выключает следование |
| Пользователь выше порога | Позицию не менять; доступна «К новым сообщениям», в том числе при поступлении дельт |
| Кнопка перехода | Плавно к актуальному концу истории, обновить позицию, включить followBottom; при reduced motion мгновенно |
| Switch | После отрисовки сообщений (например, useLayoutEffect) восстановить конец при followBottom, иначе сохранённый scrollTop в допустимом диапазоне |
| Нет записи / reload / собственный send | Показать конец, followBottom = true |
| Resize / клавиатура | Сохранить то же правило чтения; новые данные не переводят focus в историю |
| Delete | Удалить запись из Map |

Для оставленного выше чата рост в фоне не меняет место чтения. Кнопка перехода не перекрывает текст.

Плавность применяется только к «К новым сообщениям»: нативный scrollTo с behavior: smooth; 300–400 мс — ориентир, точное время задаёт браузер. Без сторонней библиотеки, глобального scroll-behavior и изменения вида/условий кнопки; focus с preventScroll. На время перехода локальный ref защищает его от мгновенного автоскролла при streaming и от промежуточных scroll-событий, возвращающих кнопку/выключающих следование. После завершения виден актуальный конец, обычный followBottom продолжается. Ручная прокрутка прерывает переход и возвращает правило 80 px; switch/delete прекращают переход старого чата и очищают временное состояние. Остальные сценарии, включая восстановление позиции и обычное автоследование, остаются без анимации. При reduced motion кнопка прокручивает мгновенно.

- Пустой экран: заголовок, пояснение демо, три примера; до двух карточек в ряд на desktop/tablet, одна на phone. Фон карточек optionSurface, без границы; заголовок text с weight 600, описание textMuted. Hover — фон темнее, focus видим.
- Ученик: справа, текст слева, более насыщенный фон userMessage, padding 14 × 22 px (phone 12 × 16); ширина ≤ 85% колонки, на phone до 100%. Подсказки и карточки примеров используют более бледный бирюзовый optionSurface: варианты визуально отличаются от отправленного вопроса. Подсказки — основной цвет текста, расстояние 16 px. ### Изображение и движение

Готовый asset второго закона Ньютона через img: вписать без обрезки и искажения, сохранить пропорции, не растягивать бесконтрольно. Размер placeholder резервируется по файлу; на 320 px изображение не расширяет страницу. Описательный alt по содержимому файла; видимой подписи и дополнительного текстового объяснения нет.

Новый живой вызов generate_image в открытом чате запускает ровно четыре CSS-этапа одновременно с tool_call:

1. Размытая область/заглушка без различимых деталей; сохраняются пропорции и скругления PNG.
2. Умеренное число пикселей 2–4 px с полупрозрачностью и мягким свечением плавно движется в разных направлениях, без хаотичного мерцания; набор/позиции стабильны между рендерами.
3. Движение прекращается, пиксели полностью исчезают через opacity; область остаётся размытой. При позднем результате ждать в этом состоянии без повторения движения.
4. Только после окончания этапа 3, успеха инструмента и загрузки файла весь PNG проявляется одновременно: blur 16 px → 0, opacity 0,25 → 1 за 1200 мс. Текст/стрелки/формулы внутри файла отдельно не анимируются.

Начальный ориентир этапов 1/2/3 — 200/1400/300 мс, суммарно меньше минимальной задержки инструмента; это параметры UI для подбора, не новая задержка агента. Ранний результат ждёт завершения этапа 3, поздний начинает этап 4 после load; completed/сохранение не ждут ни один CSS-этап. Нет градиентного прохода по изображению, вспышек, световых полос, крупных квадратов и дополнительных эффектов. Контейнер стабилен по высоте, glow/blur не выходят за его границы.

Если чат покинут во время создания и открыт до результата, показывать статичное ожидание, затем загруженный PNG сразу чётким, без повторного проигрывания. Готовая история и фоновый результат после switch/reload также чёткие. UI отличает новый переход в вызов инструмента от первого монтирования уже выполняющегося/завершённого run. CSS-прогресс не сохраняется в Redux/localStorage. Ошибка инструмента/Stop до результата прекращают эффекты и не запускают этап 4; Retry с новым runId начинает новый вызов/анимацию. Уже полученное изображение сохраняется, начавшееся проявление может закончиться после completed. При reduced motion — статичное ожидание, после load сразу чёткое изображение, без всех четырёх эффектов. Просмотр/Download разрешены только после визуальной готовности.

Обычные переходы — 120–160 мс; streaming без анимации каждого слова. При prefers-reduced-motion нет blur/opacity-анимации, плавной прокрутки и вращения: готовая картинка сразу чёткая, активность показана статически. Проверки размеров, состояний и базовой доступности — в [плане](QUALITY_REQUIREMENTS.md#ручная-приёмка).
