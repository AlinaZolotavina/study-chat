# LOM AI — Requirements

## Functional Requirements

| ID                        | Требование                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a id="fr-001"></a>FR-001 | Система должна открывать один пустой диалог «Новый диалог» при запуске без сохранённых данных.                                                       |
| <a id="fr-002"></a>FR-002 | Система должна повторно использовать выбранный пустой диалог без черновика при создании нового чата.                                                 |
| <a id="fr-003"></a>FR-003 | Система должна восстанавливать историю и черновик выбранного пользователем чата.                                                                     |
| <a id="fr-004"></a>FR-004 | Система должна формировать название чата из первого вопроса длиной не более 48 Unicode-символов с многоточием при сокращении.                        |
| <a id="fr-005"></a>FR-005 | Система должна поднимать чат в списке при создании или принятии нового вопроса.                                                                      |
| <a id="fr-006"></a>FR-006 | Система должна продолжать ответ в исходном чате после переключения пользователя в другой чат.                                                        |
| <a id="fr-007"></a>FR-007 | Система должна отмечать успешный ответ в невыбранном чате непрочитанным до открытия этого чата.                                                      |
| <a id="fr-008"></a>FR-008 | Система должна запрашивать подтверждение удаления чата с указанием его названия и последствий.                                                       |
| <a id="fr-009"></a>FR-009 | Система должна выбирать соседний чат после удаления выбранного чата либо создавать пустой диалог после удаления последнего.                          |
| <a id="fr-010"></a>FR-010 | Система должна сохранять черновик каждого чата при переключении, остановке, ошибке и повторе ответа.                                                 |
| <a id="fr-011"></a>FR-011 | Система должна отклонять отправку пустого, пробельного или превышающего 4000 UTF-16 единиц сообщения без обрезания черновика.                        |
| <a id="fr-012"></a>FR-012 | Система должна удалять только внешние пробельные символы принятого сообщения с сохранением внутренних переносов строк.                               |
| <a id="fr-013"></a>FR-013 | Система должна отправлять сообщение по Enter и вставлять перенос строки по Shift+Enter.                                                              |
| <a id="fr-014"></a>FR-014 | Система должна заполнять пустое поле ввода выбранным учебным примером без автоматической отправки.                                                   |
| <a id="fr-015"></a>FR-015 | Система должна атомарно добавлять вопрос и пустой ответ при принятии сообщения.                                                                      |
| <a id="fr-016"></a>FR-016 | Система должна запрещать второй запрос в чате до завершения активного ответа.                                                                        |
| <a id="fr-017"></a>FR-017 | Система должна показывать актуальный статус выполнения ответа.                                                                                       |
| <a id="fr-018"></a>FR-018 | Система должна постепенно дополнять ответ текстовыми фрагментами агента.                                                                             |
| <a id="fr-019"></a>FR-019 | Система должна сохранять уже полученный результат при остановке ответа.                                                                              |
| <a id="fr-020"></a>FR-020 | Система должна разрешать повтор только последнего ответа в состоянии cancelled, interrupted или failed с разрешённым повтором.                       |
| <a id="fr-021"></a>FR-021 | Система должна начинать повтор с новым запуском и очищенным результатом в прежней паре сообщений.                                                    |
| <a id="fr-022"></a>FR-022 | Система должна показывать ошибку у соответствующего ответа с сохранением его частичного результата.                                                  |
| <a id="fr-023"></a>FR-023 | Система должна объяснять второй закон Ньютона с формулой F = m · a по поддерживаемому запросу.                                                       |
| <a id="fr-024"></a>FR-024 | Система должна предоставлять упрощение, схему и пример из жизни как независимые продолжения объяснения Ньютона.                                      |
| <a id="fr-025"></a>FR-025 | Система должна решать фиксированное уравнение 3(2x − 4) + 5 = 2(x + 7) в четыре последовательных этапа без преждевременного раскрытия ответа.        |
| <a id="fr-026"></a>FR-026 | Система должна отвечать на уточнение текущего преобразования уравнения без продвижения к следующему этапу.                                           |
| <a id="fr-027"></a>FR-027 | Система должна вычислять произведение двух целых чисел от −10000 до 10000 в поддерживаемой грамматике калькулятора.                                  |
| <a id="fr-028"></a>FR-028 | Система должна распознавать утверждённые команды после нормализации регистра, пробелов и завершающей пунктуации.                                     |
| <a id="fr-029"></a>FR-029 | Система должна завершать неподдержанный запрос дружелюбным fallback-ответом с сохранением учебного контекста.                                        |
| <a id="fr-030"></a>FR-030 | Система должна использовать для учебного контекста только успешно завершённые пары сообщений своего чата до текущего вопроса.                        |
| <a id="fr-031"></a>FR-031 | Система должна показывать подсказки только у последнего успешно завершённого ответа до принятия следующего вопроса.                                  |
| <a id="fr-032"></a>FR-032 | Система должна исключать успешно использованные продолжения из актуальных подсказок после восстановления истории.                                    |
| <a id="fr-033"></a>FR-033 | Система должна отправлять актуальную подсказку через общий путь отправки с сохранением черновика.                                                    |
| <a id="fr-034"></a>FR-034 | Система должна демонстрировать по одному встроенному сбою калькулятора, потока уравнения и подготовки схемы в каждом чате.                           |
| <a id="fr-035"></a>FR-035 | Система должна считать демонстрационный сбой использованным только после принятия соответствующей ошибки активного запроса.                          |
| <a id="fr-036"></a>FR-036 | Система должна восстанавливать сохранённые чаты, сообщения, черновики и выбранный диалог после перезагрузки.                                         |
| <a id="fr-037"></a>FR-037 | Система должна восстанавливать незавершённый ответ как interrupted без автоматического повторного запуска агента.                                    |
| <a id="fr-038"></a>FR-038 | Система должна продолжать работу в памяти с уведомлением при недоступности постоянного хранилища.                                                    |
| <a id="fr-039"></a>FR-039 | Система должна отображать Markdown ответов с поддержкой абзацев, списков, заголовков и кода.                                                         |
| <a id="fr-040"></a>FR-040 | Система должна копировать полный исходный Markdown непустого завершённого или прерванного ответа без служебных данных.                               |
| <a id="fr-041"></a>FR-041 | Система должна сообщать об отказе копирования без ложного подтверждения успеха.                                                                      |
| <a id="fr-042"></a>FR-042 | Система должна открывать готовое изображение в полноразмерном просмотре с возвратом фокуса после закрытия.                                           |
| <a id="fr-043"></a>FR-043 | Система должна скачивать исходный PNG под именем lom-ai-newton.png из сообщения и полноразмерного просмотра.                                         |
| <a id="fr-044"></a>FR-044 | Система должна показывать ошибку скачивания с возможностью последующего повторного действия.                                                         |
| <a id="fr-045"></a>FR-045 | Система должна показывать схему через этапы blur, particles, fading и revealing с проявлением PNG только после исчезновения частиц и загрузки файла. |
| <a id="fr-046"></a>FR-046 | Система должна показывать восстановленную или подготовленную в фоне схему без повторной анимации.                                                    |
| <a id="fr-047"></a>FR-047 | Система должна показывать историю фактически завершённых высокоуровневых действий агента в порядке выполнения.                                       |
| <a id="fr-048"></a>FR-048 | Система должна сохранять состояние раскрытия истории действий отдельно для каждого ответа.                                                           |
| <a id="fr-049"></a>FR-049 | Система должна показывать длительность успешного ответа от принятия запроса до завершения с учётом очереди.                                          |
| <a id="fr-050"></a>FR-050 | Система должна восстанавливать позицию чтения при переключении между чатами.                                                                         |
| <a id="fr-051"></a>FR-051 | Система должна сохранять позицию чтения при поступлении текста, если пользователь находится дальше 80 px от конца истории.                           |
| <a id="fr-052"></a>FR-052 | Система должна переводить историю к актуальному концу по кнопке «К новым сообщениям».                                                                |
| <a id="fr-053"></a>FR-053 | Система должна предоставлять навигацию по чатам через боковую панель и мобильное меню.                                                               |
| <a id="fr-054"></a>FR-054 | Система должна открывать справку с описанием доступных демо-сценариев без изменения текущего диалога.                                                |
| <a id="fr-055"></a>FR-055 | Система должна отображать ошибку загрузки PNG внутри контейнера изображения.                                                                         |

## Quality Requirements

| ------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |

| <a id="qr-002"></a>QR-002 | Надёжность               | Система должна сохранять терминальный результат неизменным при поступлении поздних событий.                                                            |
| <a id="qr-003"></a>QR-003 | Надёжность               | Система должна завершать зависший запрос ошибкой timeout по истечении настроенного лимита ожидания.                                                    |
| <a id="qr-004"></a>QR-004 | Надёжность               | Система должна завершать запрос нормализованной ошибкой при исключении агента или окончании итератора без терминального события.                       |
| <a id="qr-005"></a>QR-005 | Ресурсы                  | Система должна освобождать таймеры и подписки завершённой либо отменённой операции.                                                                    |
| <a id="qr-006"></a>QR-006 | Сохранность данных       | Система должна сохранять исходную повреждённую запись хранилища неизменной в течение сессии.                                                           |
| <a id="qr-007"></a>QR-007 | Целостность текста       | Система должна восстанавливать исходный Markdown точной конкатенацией фрагментов без разрыва Unicode code points.                                      |
| <a id="qr-008"></a>QR-008 | Время ответа             | Система должна завершать каждый подготовленный текстовый сценарий не более чем за 4 секунды при штатных таймерах и максимальных настроенных задержках. |
| <a id="qr-009"></a>QR-009 | Время ответа             | Система должна завершать запрос калькулятора менее чем за 3 секунды при максимальных настроенных задержках.                                            |
| <a id="qr-010"></a>QR-010 | Время ответа             | Система должна выдерживать настроенную задержку подготовки схемы от 2500 до 3500 мс после анализа.                                                     |
| <a id="qr-011"></a>QR-011 | Производительность       | Система должна сохранять результат селектора подсказок при изменении черновика или данных другого чата.                                                |
| <a id="qr-012"></a>QR-012 | Хранение                 | Система должна откладывать обычную запись изменений на 400 мс после последнего изменения.                                                              |
| <a id="qr-013"></a>QR-013 | Хранение                 | Система должна немедленно сохранять структурные изменения чатов, завершение ответа, отметку сбоя и раскрытие истории действий.                         |
| <a id="qr-014"></a>QR-014 | Безопасное представление | Система должна оставлять ссылки с протоколами, отличными от HTTP(S), неактивными.                                                                      |
| <a id="qr-015"></a>QR-015 | Безопасное представление | Система должна отклонять изображения вне разрешённых локальных путей assets/.                                                                          |
| <a id="qr-016"></a>QR-016 | Безопасное представление | Система должна отображать сообщения без исполнения встроенного HTML.                                                                                   |
| <a id="qr-017"></a>QR-017 | Доступность              | Система должна обеспечивать выполнение основных действий с клавиатуры с видимым фокусом.                                                               |
| <a id="qr-018"></a>QR-018 | Доступность              | Система должна удерживать фокус внутри открытого модального окна с возвратом к доступному элементу после закрытия.                                     |
| <a id="qr-019"></a>QR-019 | Контраст                 | Система должна обеспечивать контраст обычного текста и placeholder не менее 4,5:1.                                                                     |
| <a id="qr-020"></a>QR-020 | Контраст                 | Система должна обеспечивать контраст крупного текста и информативных границ, иконок и индикаторов фокуса не менее 3:1.                                 |
| <a id="qr-021"></a>QR-021 | Совместимость            | Система должна сохранять доступность основных действий без горизонтального переполнения страницы в Chrome при ширинах 320, 390, 768, 1024 и 1440 px.   |
| <a id="qr-022"></a>QR-022 | Масштабирование          | Система должна сохранять доступность ввода и основных действий при масштабе 200% и малой высоте окна.                                                  |
| <a id="qr-023"></a>QR-023 | Движение                 | Система должна отключать анимацию схемы, декоративное движение и плавный переход истории при prefers-reduced-motion.                                   |
| <a id="qr-024"></a>QR-024 | Учебная корректность     | Система должна давать для фиксированного уравнения решение x = 21/4 = 5,25 с проверкой равенства обеих частей 24,5.                                    |
| <a id="qr-025"></a>QR-025 | Проверяемость            | Система должна воспроизводить одинаковый поток текста при одинаковых входных данных, конфигурации и внедрённом источнике случайности.                  |
| <a id="qr-026"></a>QR-026 | Ресурсы                  | Система должна освобождать временный URL и элемент скачивания при успехе, ошибке или отмене скачивания.                                                |
| <a id="qr-027"></a>QR-027 | Размещение               | Система должна разрешать локальный путь изображения относительно базового пути публикации.                                                             |

Порог обычного и крупного текста опирается на [WCAG: Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html); 3:1 для информативных границ, иконок и focus — согласованный проектный порог. Ручная проверка доступности не является полным аудитом WCAG.
